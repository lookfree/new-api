## P2a 模型广场分区

**现状**：`/pricing` 已有供应商、标签、分组、搜索、卡片与表格两种视图、模型详情。`GET /api/pricing` 的每个模型带 `tags` 与 `vendor_id`，响应里另带 `vendors` 列表。

**做法**

后端只加一个配置项，不动表结构：

- `model/option.go` 的 `InitOptionMap` 注册 `VendorZones` 默认值为空串。`updateOptionMap` 对未知键是通用写入，`validateOptionValue` 也不拒绝未知键，所以不需要额外的 switch 分支。
- `controller/pricing.go` 的响应里多返回一个 `vendor_zones` 字段，取自 `common.OptionMap["VendorZones"]`。这是对上游文件的唯一改动，只有一行。

配置项的值是 JSON，把供应商 id 分到两个区：

```json
{ "domestic": [1, 2, 3], "international": [4, 5] }
```

未出现在映射里的供应商归入「其他」，不会因为漏配而从列表里消失。

前端在模型广场顶部加一层分区 Tab：全部 / 国内大模型 / 国外大模型，与原型一致。Tab 只过滤当前结果集，与现有的供应商、标签、分组筛选叠加生效。分区解析和过滤放在 `features/pricing/lib/` 下的新文件里，带单元测试，覆盖空配置、未知供应商、只配了一边这几种情况。

卡片样式按原型调整：供应商名、上下文长度、输入与输出单价、能力标签。

**边界**：配置项为空时，Tab 整条不渲染，页面回到现在的样子。

## P2b 首页重排

**原型顺序**：Hero、特性、模型展示、价格、CTA、页脚。
**现状顺序**：Hero、统计、特性、工作原理、CTA、页脚。

**做法**

- 统计并入 Hero 左栏下方，与原型一致，删掉独立的 Stats 区块。
- Hero 右栏换成原型的语言 Tab 代码块，展示 cURL、Python、Node 三种调用示例。
- 新增模型展示区块，复用 P2a 的模型卡片，取启用模型的前若干个。
- 新增价格区块，展示热门模型的输入输出单价表，与原型的价格表一致。
- 删掉工作原理区块。
- 清掉 `features/home` 里剩余的蓝紫硬编码色，全部改走主题变量。

后台配置了 `HomePageContent` 时仍走原有的整页覆盖逻辑，这条分支不动。

## P2c 文档页

**现状**：导航里的「文档」在没有配置外链时指向 `/docs`，而该路由不存在，点过去是 404。

**做法**

新建 `/docs` 路由与 `features/docs`，按原型分六节：快速开始、鉴权、调用示例、模型列表、计费、错误码。右侧目录锚点跟随滚动。

接口地址不写死，从后台 `ServerAddress` 取，未配置时回退到当前站点的 origin，保证示例可直接复制运行。文案走 i18next，中英双语。

## P2d 联系我们

**做法**

前端新建 `/contact` 路由与 `features/contact`，按原型展示邮箱、客服微信二维码、企业微信、电话，以及留言表单。表单用 React Hook Form 加 Zod 校验。

后端新增 `POST /api/contact`，限流复用 `middleware.CriticalRateLimit()`，并接 Turnstile 人机校验，防刷。处理逻辑是把留言拼成邮件，用现有的 `common.SendEmail` 发到后台配置的收件邮箱。相关配置项：

- `ContactEmail` 收件邮箱，为空时接口直接返回未启用
- `ContactInfo` 页面展示的联系方式 JSON，含微信二维码图片地址、企业微信、电话

导航里把「关于」替换为「联系我们」，或两者并存，取决于运营是否还要保留关于页。默认两者并存。

**边界**：未配置 SMTP 或收件邮箱时，页面仍展示联系方式，表单区域给出提示而不是报错。

## 通用约束

- 前端文案一律走 i18next，键用英文原文，同步到 `zh` 与 `en`。
- 每次改动跑 `bun run typecheck`，并对改动文件跑 lint，不留 error。
- 纯逻辑（分区解析、价格格式化）配单元测试，放在模块自己的 `__tests__/` 下。
- 不修改上游的 new-api 与 QuantumNous 署名、版权头、页脚归属。
- 对上游已有文件的改动尽量少，新代码优先落在新增文件里，便于 rebase。
