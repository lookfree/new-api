## 1. 生产构建验证

此前所有页面都只在开发服务器上验证过，而真正的部署路径不同：前端构建产物会嵌进 Go 二进制，由内置的静态路由提供服务。这条路径没验过就是风险，路由生成、资源路径、静态托管都可能与开发环境表现不一致。

因此完整走了一遍：清空前端产物重新构建，编译带嵌入资源的二进制，起一个全新实例并灌入演示数据，逐页验证。

结果：首页、模型广场、开发者文档、联系我们四个公开页在生产构建下全部正常。分区 Tab、接口地址从后台配置读取、联系方式卡片、表单，行为与开发环境一致。

结论：本次新增的四个前端路由都能被内置静态路由正确托管，没有仅在开发环境成立的假象。

## 2. 部署方式

镜像分三段构建：bun 构建前端、golang 编译并嵌入产物、debian slim 承载运行。容器内监听 3000。

`docker-compose.yml` 已包含 new-api、Redis、PostgreSQL 三个服务。本机开发时端口冲突的处理放在被 gitignore 的 `docker-compose.override.yml` 里，不进仓库。

### 上线前必须修改的项

`docker-compose.yml` 里全部是示例值，直接上线等于把数据库和缓存的口令公开：

- `POSTGRES_PASSWORD` 与 `SQL_DSN` 里的口令，改成强口令并保持一致。
- Redis 的 `--requirepass` 与 `REDIS_CONN_STRING` 里的口令，同上。
- `SESSION_SECRET` 必须设成随机字符串。多节点部署时若不设，各节点签发的会话互不认识，用户会随机掉线。
- `SESSION_COOKIE_SECURE=true` 与 `SESSION_COOKIE_TRUSTED_URL` 填正式域名。前者启用 Secure Cookie 和严格的来源校验，只有在 HTTPS 下才能开。
- `TRUSTED_PROXIES` 填反向代理的网段。不设时会信任内网地址并打告警，生产环境应显式指定，否则客户端 IP 可被伪造，限流形同虚设。

### 必须持久化的目录

- `/data` 数据目录。用 SQLite 时数据库文件在这里，丢了等于丢全部数据。
- `/app/logs` 日志目录。

### 数据库选择

三种数据库都支持，本项目的迁移已在 SQLite、MySQL 8.2、PostgreSQL 15 上验证过。生产建议 PostgreSQL，compose 默认即是。SQLite 仅适合单机小流量，且不支持多节点。

日志量大时可以把日志库拆到单独的 `LOG_SQL_DSN`，compose 里已有注释示例。

## 3. 反向代理与 HTTPS

对外必须走 HTTPS，否则 Secure Cookie 开不了，微信和支付回调也不会接受。

反向代理需要注意两点：

- 转发 `X-Forwarded-For` 与 `X-Forwarded-Proto`，并把代理网段写进 `TRUSTED_PROXIES`，限流和审计日志才能拿到真实客户端 IP。
- 流式响应必须关闭缓冲。对话补全是 SSE 长连接，若代理缓冲响应，用户会看到卡住不动直到请求结束。Nginx 下需要关闭 `proxy_buffering`，并把读超时调长到超过最长的一次生成。

## 4. 上线前的配置清单

以下都在后台设置里填，不需要改代码重新发版：

- 站点：系统名称「智航通」、Logo 指向 `/zetone-logo.svg`、页脚、`ServerAddress` 填正式域名。`ServerAddress` 同时是文档页示例、OAuth 回调、支付回调的基准地址，填错会连锁出问题。
- 导航：`HeaderNavModules` 控制顶部导航各项的显隐。
- 模型：逐个模型填供应商、标签、描述，并配置 `VendorZones` 把供应商分到国内与国外两区。这是数据录入工作，量取决于上线多少模型，预留半天到一天。
- 登录方式：邮箱始终可用；手机号填 `sms.*` 一组配置；GitHub 与 Google 填各自凭据；微信等资质。
- 返利：`affiliate.enabled` 与 `affiliate.rate`，默认关闭、比例 0.1。
- 联系页：`ContactEmail` 收件邮箱与 `ContactInfo` 联系方式。
- 人机校验：Turnstile 建议开启，注册、发送验证码、联系表单都会受其保护。
- 条款与隐私：正文必须补齐，目前仍是占位文本。

## 5. 备份

至少要有两样：数据库定时备份并异地留存，以及备份的恢复演练。没演练过的备份等于没有备份。

用 PostgreSQL 时用 `pg_dump` 定时导出；用 SQLite 时直接备份 `/data` 目录，但要在服务停止或使用 SQLite 在线备份的前提下进行，直接复制正在写入的文件可能得到损坏的副本。

## 6. 被资质卡住的事项

这些不是技术问题，需要运营并行推进，详见 P3 设计文档第 0 节。

| 事项 | 卡在什么 | 影响 |
|---|---|---|
| 域名与 HTTPS | ICP 备案，1 到 3 周 | 支付回调、微信登录、Secure Cookie 全都依赖它，是最长的一环 |
| 支付宝与微信支付 | 企业资质加已备案域名 | 用户无法充值，等于无法产生收入 |
| 微信扫码登录 | 微信开放平台网站应用审核 | 少一种登录方式，手机号与邮箱可顶替 |
| 短信签名与模板 | 阿里云签名报备，1 到 2 个工作日 | 手机号登录发不出验证码。凭据可复用现有阿里云账号，但签名与模板需为智航通单独报备 |

在这些落地之前，系统仍可完整运行：手机号登录用日志实现联调，充值走兑换码或管理员补单，微信登录关闭即可。

## 7. 建议的上线顺序

1. 买域名，立即启动 ICP 备案。这是关键路径，其余事项都在它后面。
2. 备案期间：申请阿里云短信签名、GitHub 与 Google 的 OAuth 凭据，这三样不需要域名就能先办。
3. 准备服务器，用正式口令部署一套，先内部试用。
4. 录入模型与供应商数据，配置分区。
5. 备案通过后：绑定域名、配 HTTPS、开 Secure Cookie、接支付、提交微信开放平台。
6. 补齐服务条款与隐私政策正文，然后对外开放注册。
